# P3 Web + extension plan (approved by the human 2026-11-12: H1–H7 as proposed)

Scope comes from OFFERLANE_V4.md P3 and D2/D3/D4. The web app and the extension keep D3: resume/profile text stays on the client, AI calls go from the browser with the user's own key, and only ciphertext reaches `/v1/sync`.

## Decisions needed before code (human)
H1. Layout. `libs/core` (not `packages/core`: macOS case, P0 note 7), `apps/web`, `apps/extension`. The web app uses `Packages/design-tokens/tokens.css` as is (already generated by `scripts/gen_tokens.py`); no new token pipeline.
H2. Web stack. Proposal: Vite + React + TypeScript strict, no UI kit, no router library (one `view` state + URL hash; SHORTCUT). Alternative: Preact (smaller) or SvelteKit.
H3. Web data. Proposal: everything lives in IndexedDB on the device. Signed in, it syncs through `/v1/sync` exactly per docs/v4/SYNC_CRYPTO.md (WebCrypto AES-GCM, printed recovery key). The AI key is held in memory by default; "remember on this device" stores it in IndexedDB wrapped by a non-extractable WebCrypto key. Strict CSP (no inline script, `connect-src` = API + the curated AI hosts only).
H4. Auth. The provider (P2 H2) is still open, so sign-in works against `test/devIssuer.ts` locally. The browser does OIDC code + PKCE; web works fully signed out (local only). The real provider plugs in later by config.
H5. Extension. Proposal: Chromium MV3 first (Chrome/Edge/Brave); Firefox later, Safari after the Developer ID. Permissions: `activeTab`, `scripting`, `storage` only, no host permissions, no remote code. It talks to the web app through `externally_connectable` (Offerlane web origin only): the web app hands it the answer set, the extension hands back saved jobs. No server and no account needed.
    Save job = read the open tab's JSON-LD `JobPosting` or a known ATS URL. Assisted apply = a side panel on the form page with copy-ready answers (AnswerRules port). It never fills, never clicks submit (D4, Protocol 11).
H6. Regional pay and sources. Proposal: `PayRange.parse` learns GBP/EUR/INR/CAD/AUD and formats like `£45k`, `€45.000`, `₹12 LPA`, `per annum`, day/month rates, in Swift and TS from one fixture. Sources: Adzuna's country list moves into a shared JSON (both ports read it). No new job sources without a terms decision.
H7. Dependencies (Protocol 7). Versions pinned at install, 14-day minimum age already enforced.

## Not in P3
Mac app calling the cloud (sync, `/v1/jobs`) stays for a later phase. Firefox/Safari extension builds. Store submission (needs a developer account: HUMAN BLOCKER). Hosting the web app (P2 H3).

## Risks
- An AI key in a browser is exposed to any XSS on our origin: strict CSP, no third-party scripts, React escaping only, no `dangerouslySetInnerHTML`.
- Browser-direct AI needs CORS from the provider; OpenRouter and Anthropic allow it today. A provider that doesn't is Mac-only.
- Two ports drift: the parity gate makes any drift a red build, not a silent difference.
- Store review may reject `externally_connectable` or side-panel use; the checklist covers it before submission.
- PDF output on web is the browser's print, not the Mac LaTeX render; the review screen says so.
